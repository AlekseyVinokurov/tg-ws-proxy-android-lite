# TG WS Proxy — Pixel Eco

Экспериментальный **локальный MTProto-прокси для Telegram** под Android с акцентом на снижение фоновой активности. Основа — [amurcanov/tg-ws-proxy-android](https://github.com/amurcanov/tg-ws-proxy-android). Исходные авторы и лицензия GPLv3 сохранены.

Это **отдельное приложение**, не VPN и не альтернативный Telegram-клиент. Оно запускает локальный прокси, который нужно выбрать в Telegram.

## Чем отличается Pixel Eco

- Убран постоянный частичный CPU wake lock; управляемая вручную служба по-прежнему работает как Android foreground service.
- Фоновое обновление статистики сокращено до одного раза в **60 секунд**.
- По умолчанию **один** предварительно подключённый WebSocket. Доступны значения **0, 1, 2, 4**. Меньший пул экономит фоновую активность, но может увеличивать задержку первого соединения.
- Локальный порт по умолчанию — **1444**, чтобы не конфликтовать с другой установленной версией на 1443.
- Отдельный `applicationId`: `com.amurcanov.tgwsproxy.pixel8lite`; можно установить рядом с исходным приложением.
- Автозапуск при включении телефона **выключен по умолчанию**.

Снижение расхода батареи пока не измерено в контролируемых условиях. Это экспериментальные настройки, а не гарантированное улучшение.

## Резервный режим для мобильных сетей — кандидат

Добавлен отдельный режим **Cloudflare WS/80 без TLS** для случаев, когда TCP-подключение есть, но защищённый WebSocket через мобильную сеть не устанавливается.

1. Остановите прокси и откройте **Настройки**.
2. Оставьте Cloudflare включённым и выберите **«Резервный Cloudflare WS/80 без TLS»**.
3. Прочитайте предупреждение о безопасности, подтвердите выбор и снова запустите прокси.
4. Подключите локальный прокси в Telegram и проверьте загрузку реальных сообщений и медиа.

Движок сначала пробует защищённый **WSS/443**: TLS-сертификат проверяется для базового домена Cloudflare, а HTTP Host остаётся `kwsN.<домен>`. Если защищённый маршрут недоступен по сетевой причине, разрешён резервный **WS/80**. Ошибка проверки сертификата или HTTP-ответ сервера не должна запускать такой переход. Прямые WebSocket-маршруты Telegram и TCP fallback не меняются.

**Ограничение безопасности:** в WS/80 нет дополнительного TLS до Cloudflare. Содержимое Telegram продолжает шифроваться через MTProto, но сетевые метаданные защищены слабее. Резервный режим **выключен по умолчанию**. Его работоспособность зависит от оператора и сети.

Отдельный APK Pixel Eco с этим изменением **пока не проверен на устройстве**. Похожий механизм WS/80 реально работал в [Velora 0.1.5](https://github.com/AlekseyVinokurov/Velora/releases/tag/v0.1.5) на одном Pixel 8. Это не подтверждает работу самостоятельного приложения.

## Выпуск и обновление приложения

Начиная с подготовленной версии **1.2.4**, релизная сборка использует **постоянный ключ**, зашифрованный в репозитории; пароль хранится только в защищённом GitHub Actions environment `pixel-eco-release`. Ключ создаётся один раз workflow [Bootstrap signing](.github/workflows/bootstrap-signing.yml), повторная генерация запрещена. Пароль длиной не менее 32 символов сохраняет владелец в менеджере паролей и GitHub Secret `PIXEL_ECO_RELEASE_KEY_PASSPHRASE`. Никому не отправлять.

После однократного создания ключа workflow [Publish signed Pixel Eco APK](.github/workflows/release-pixel-eco.yml) на облачном GitHub-hosted runner пересобирает Rust и Android, подписывает APK **тем же ключом**, сверяет сертификат с зафиксированным SHA-256 и публикует GitHub Release. Никаких локальных Android-сборок.

**Старая версия `pixel8-stable-go-v1` была подписана временным debug-ключом, который не сохранён. Установить новую версию поверх неё невозможно.** Первый переход потребует удаления старого Pixel Eco, что удалит его настройки. Далее, при сохранении постоянного ключа и `applicationId`, штатные обновления устанавливаются поверх приложения.

Встроенный updater скачивает только APK из стабильного GitHub Release, проверяет GitHub SHA-256, `applicationId`, `versionCode` и совпадение сертификата с установленным приложением. Затем запускает системный установщик Android, требующий подтверждения пользователя. До выпуска версии 1.2.4 этот механизм ещё не доступен в публичном APK.

## Сетевые эксперименты и TXT-диагностика

В настройках можно независимо включить: **резервный WS/80**, проверяемый **TLS SNI для kwsN** вместо базового домена и **DoH-first** (сначала полученный через DoH адрес), а также **DPI-эксперимент: HTTP-заголовки WS/80** — меняет порядок заголовков и User-Agent для сравнения при включённом WS/80. Эти параметры влияют на соединения и могут ухудшить стабильность. Это измерительные опции, а не гарантированный обход DPI.

Переключатель **«Записывать диагностический журнал»** включается до старта прокси. Ограниченный журнал хранится только локально, продолжает собираться в фоновой службе и содержит сетевые события, IP/домены, тип сети и счётчики WSS/WS80. В разделе **«Логи»** нажмите **«Сохранить TXT-диагностику»**: Android предложит выбрать файл. Перед отправкой прочитайте содержимое: IP-адреса и сетевые метаданные могут быть личной информацией. Секреты и длинные шестнадцатеричные токены маскируются, но автоматическая маскировка не заменяет ручную проверку.

## Установка и использование

Опубликованные APK доступны в [Releases](https://github.com/AlekseyVinokurov/tg-ws-proxy-android-lite/releases). Тестовые сборки новых изменений — в [Actions](https://github.com/AlekseyVinokurov/tg-ws-proxy-android-lite/actions).

1. Установите APK и откройте **TG WS Proxy Pixel Eco**.
2. Оставьте WS pool = **1**, выберите свободный порт (по умолчанию **1444**) и нажмите **Start proxy**.
3. Нажмите **Apply in Telegram**, чтобы включить локальный MTProto-прокси.
4. Проверьте сообщения и медиа, в том числе при переключении Wi-Fi ↔ мобильная сеть.
5. Если приложение не требуется, остановите прокси вручную.



## Исходники и сборка

Workflow [`build-pixel8.yml`](.github/workflows/build-pixel8.yml) запускается **только на облачном GitHub-hosted runner**: тестирует Rust-код, заново собирает ARM64 `libtgwsproxy.so` и затем формирует debug APK. Сама успешная компиляция ещё не доказывает, что прокси работает на мобильной сети.

Каталог `old_src_golang/` содержит архивный Go-код; он **не используется** в новом процессе сборки Rust. Отсутствовавший `src/faketls.rs` восстановлен из исходного проекта с сохранением GPLv3.

Ограничения: основная архитектура ARM64, нет приёмки на других устройствах и операторах, автоматические обновления тестовых APK не подтверждены. Универсального обхода блокировок приложение не гарантирует.

Для ошибок и предложений используйте [GitHub Issues](https://github.com/AlekseyVinokurov/tg-ws-proxy-android-lite/issues).
